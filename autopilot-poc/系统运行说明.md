# 营销 Agent 编排层（Autopilot PoC）系统运行说明

> 文档目的：说明本系统「目前是怎么运行的」，供你核对是否与预期需求一致。
> 最后更新：2026-09-08

---

## 一、系统是什么（一句话）

一个坐在 Mautic 前面的**营销活动编排层**：运营用大白话描述「给谁、推什么、达到什么目标」，
系统把它**编译成 Mautic 能直接跑的自动化 campaign 流程图**，自动注入合规/频次/审批管控，
并在活动跑起来后**自动回填真实执行数据（发送/打开/点击/转化/退订）**，形成「编排 → 审批 → 执行 → 复盘」闭环。

---

## 二、运行环境（两个进程）

| 进程 | 地址 | 角色 |
|------|------|------|
| **cockpit.py（驾驶舱）** | `http://127.0.0.1:8090` | 编排层 Web UI，运营操作入口 |
| **Mautic** | `http://localhost:8080` | 被调用的营销自动化平台（真正发邮件的地方） |

关系：驾驶舱是独立进程，**经 REST API 调用 Mautic**，不碰 Mautic 库/UI。Mautic 升级不影响驾驶舱。

```bash
cd autopilot-poc
python cockpit.py              # 启动驾驶舱，监听 127.0.0.1:8090
```

## 三、模块构成（按 L0–L7 分层）

| 模块 | 层 | 职责 |
|------|-----|------|
| `goal_intake.py` | L0 目标输入 | Brief → 结构化 `GoalSpec`；含**画像包推断**（多画像） |
| `strategy_spec.py` | L1 策略 | 加载 Agent 产出的 `StrategySpec`（分群/邮件/频次/tag） |
| `plan_compiler.py` | L2 编译 | `GoalSpec` → 事件图提案 `CampaignProposal`（治理注入 + `plan_hash`） |
| `approval_gate.py` | L3 审批 | 审批门（T1–T4 分级 + `plan_hash` 绑定 + 超时 EXPIRED） |
| `adaptive.py` | L1/L2/L6 | Goal → Program（N 个 campaign）；上游完成后确定性改写下游 |
| `mautic_client.py` | 对接层 | REST API 推送/读取 Mautic（OAuth2）+ 拉 Stats 真实数 |
| `cockpit.py` | UI 层 | `:8090` Web 服务（零依赖 `http.server`） |
| `auto_feedback.py` | 定时任务 | 每日汇总昨日各 campaign 的 Mautic 真实执行数 |
| `live_push.py` | 工具 | 真实推送脚本（连 Mautic 取 segment/email 引用） |

## 五、各环节详解

### ⑤ ① 填 Brief（`GET /brief`）

运营**只填业务意图**，治理/渠道/频次由系统自动决策（只读展示）。

- **AI 意图识别**（DeepSeek）：点「✨ AI 识别意图」把自然语言营销目标解析成结构化字段，
  覆盖**除营销目标输入框外的全部 16 个字段**（简称/日期/年龄/性别/收入/渠道来源/教育/行业/地区/语言/预算/是否营收/转化率/约束/策略）。
  当活动周期 ≥7 天（或设了转化目标）时，还会**自动合成多波次 StrategySpec**（无需上传 JSON）。
- **目标人群特点**：年龄段、教育经历、行业、首选来源、国家/地区、语言 **6 个字段支持多选**（性别、月收入档单选）。
- **画像包匹配**：按打分公式自动匹配画像包（HNW_FAMILY / YOUNG_TREND / PARENT_FAM / CORP_GRP / DORMANT）。
  **一个 contact 可命中多个画像包**（所有 score ≥ 0.6 的），命中多画像时策略取各画像的最大值。

### ⑤ ② 编译（`POST /brief`）

1. `parse_brief` 解析成 `GoalSpec`（校验营销目标非占位、画像包推断）。
2. `build_program` 生成 Program：N 个 campaign（N 由 StrategySpec 长度或总体目标转化率反推）。
3. 每个 campaign 绑定派生计划（转化目标 + 执行窗口），写入 `output/program_<goal_id>.json`。

### ⑤ ③ Program 流水线（`GET /program/<id>`）

展示 N 个 campaign 的状态、策略摘要、事件图（SVG 流程图）、审批/推送/回填/完成入口。

- **事件图**：每个 campaign 一份 Mautic 事件图（决策/护栏/频次闸门/锚点仲裁/邮件发送/落地页点击/打标等 13 节点）。
- **Mautic 资产外链**：已连接的邮件/分群/落地页可直接点击跳转 Mautic 详情页。
- **campaign 名字联动**：未生成时显示内部 cid（如 `svctest_c1`）；生成后显示 Mautic 实时名字并可点击跳转。

### ⑤ ④ 审批门（`POST .../campaign/<cid>/approve`）

按营收/渠道/locale 分级，**绝不默认批准**：

| 门 | 触发条件 | 说明 |
|----|---------|------|
| T2 | 单渠道 + 单 locale + 无营收 | 人工审批（门槛最低） |
| T3 | 多渠道 或 跨 locale | 人工 + 复核 |
| T4 | 涉营收 / 写 inventory | 高级审批人（最严格） |

审批时锁定 `plan_hash`（审批内容与执行内容绑定，防篡改）。

### ⑤ ⑤ 推送 Mautic（`POST .../campaign/<cid>/push`）

`mautic_client` 经 OAuth2 调 Mautic 的 `/api/campaigns`，创建 campaign（isPublished=False）并写入 events + canvasSettings。**推送时校验 plan_hash**，不一致直接拒绝。无凭证则 dry-run（只打印 API 调用清单）。

### ⑤ ⑥ 回填（三档，`feedback_auto[date]`）

| 档 | 触发 | 行为 |
|----|------|------|
| Plan 1 | 每日 06:00（WorkBuddy 定时任务） | `auto_feedback.py` 汇总昨日所有 campaign 的 5 指标 |
| Plan 2 | 点「📊 从 Mautic 拉数据预填」 | 从 Stats API 拉最新数预填表单，运营微调后保存 |
| Plan 3 | 手动改后「💾 保存」 | 人工回填（兜底） |

5 指标 = 发送数 / 打开数 / 点击数 / 转化数 / 退订数。数据来自 Mautic Stats API（email_stats / page_hits / form_submissions / lead_donotcontact）。**转化不依赖 form**——落地页 page.hit 即视为转化信号。

### ⑤ ⑦ 完成回写（`POST .../complete`）

上游 campaign 完成后，按「达成率 + 退订率」**确定性改写下游**（非 LLM 临场发挥）：

- 达标（≥目标）：保持，略降本（降频）
- 未达标（≥50%）：提频 + 换内容变体 + urgency tag
- 乏力（<50%）：大幅提频 + 扩分组 tag(broaden/reengage) + 换内容
- 退订率超阈（>0.3%）：降频 + suppression tag（收窄）

## 六、状态机（7 态）

```
unreviewed ──审批──▶ reviewed ──推送──▶ approved_idle ──执行──▶ executing
   │                                                              │
   │(外部事件挂起)                                                  │完成回写
   ▼                                                              ▼
deferred                                              done_met(已达标) / done_below(未达标)
```

| 状态 | 中文 |
|------|------|
| `unreviewed` | 未审核 |
| `reviewed` | 已审核 |
| `approved_idle` | 已审核-未执行 |
| `executing` | 执行中 |
| `done_met` | 已完成-已达标 |
| `done_below` | 已完成-未达标 |
| `deferred` | 已挂起（外部事件） |

## 八、当前能力边界（已实现 vs 未实现）

**已实现**：

- ✅ 自然语言 Brief → AI 意图识别（16 字段）→ 结构化 GoalSpec
- ✅ 策略规格三条来源：手动贴 JSON / 「自动生成策略」按钮直连 DeepSeek / 意图识别长周期自动合成
- ✅ 多选受众字段 + 多画像匹配 + 多画像策略取最大值
- ✅ Goal → Program（N 个 campaign）+ 事件图编译 + 治理注入（4 类治理节点 + 9 埋点 + mtc_* 归因）
- ✅ 审批门（T2/T3/T4 分级 + plan_hash 防篡改 + 超时 EXPIRED）
- ✅ 推送 Mautic（OAuth2，dry-run 感知）+ 资产外链 + campaign 名字联动
- ✅ 自适应改写下游（按达成率/退订率，确定性规则）
- ✅ 三档回填（每日定时 / 一键预填 / 手动）

**未实现 / 边界（PoC 明确不做）**：

- ❌ L5 观测、L6 复盘、L7 报告的完整实现（仅接口/占位）
- ❌ 真实 Mautic 事件图的**在线修改**（普通 API 改不了，须走 applyAction；目前仅新建时一并写入）
- ❌ 短信 / push / whatsapp 真实发送（仅 email 落地，其余 reserved 占位）
- ❌ 生产环境凭证（`config.json` prod 段 client_id/secret 为空，未接生产）

## 九、与需求核对要点（供自查）

1. **是否要「AI 自动决策」？** 当前：渠道/频次/治理由系统固定规则注入，策略内容由 WorkBuddy 生成 StrategySpec。
2. **是否要「多画像取最大值」？** 已支持：多选字段 → 多画像命中 → 策略取各画像最大值（频次取 max、levers 取并集、CTA 取最强）。
3. **是否要「真实数据回填」？** 已支持：三档回填，数据来自 Mautic Stats API，转化不依赖 form。
4. **是否要「审批流」？** 当前为**单次人工审批**（填 approver 名），无多级账号/权限体系（PoC 无账号系统）。
5. **是否要「闭环复盘/自动优化」？** 当前仅确定性改写下游（规则化），无 LLM 临场优化、无 L6/L7 报告。
